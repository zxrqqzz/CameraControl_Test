## 二、视觉主题：极简底 + 半调波普（Halftone Pop）

一句话：**背景不许有颜色，颜色只许出现在"能点/已选/有状态"的地方。**

### 文件分工（都在 `src/CameraControl.Presentation/Themes/`）

| 文件 | 管什么 | 什么时候改 |
|---|---|---|
| `Tokens.xaml` | 颜色、字体、字号、圆角令牌 | **换色/换字体只改这里** |
| `Controls.xaml` | 单控件长什么样（按钮/输入/列表/表格/滚动条…） | 控件观感不对时 |
| `AppStyles.xaml` | 页面怎么拼（顶栏/侧栏/状态栏/标题块/空状态/横幅） | 加页面骨架时 |
| `Converters.xaml` | 转换器实例 | 新增转换器时 |

四份都在 `App.xaml` 里用**相对路径**合并。删掉或改错名字会在启动时直接炸——
这是刻意的：样式没加载必须立刻暴露，不能悄悄退回系统默认皮肤。

### 分界线（写界面前先看这 7 条）

1. **背景极简**：窗口 `#FBFBF9`、卡片/顶栏/侧栏/状态栏/卡片标题区全白，
   结构只靠黑线（卡片 2px，顶栏/侧栏/标题条 1~2px，列表行 1px 浅灰 `#E6E6DE`）。
   **背景、表头、大色块一律不上色**——上了就不极简了。
2. **交互才上色**：明黄 `#FFD400` + 半调网点只出现在能点/能选/有状态处——
   主按钮、次按钮悬停、导航与列表选中、页签选中、复选/单选勾选、下拉箭头块、
   输入聚焦底、徽标、工具提示、页标题块、小节标题块。
3. **网点参数**：6px 一格、12% 黑圆点（`PopYellowHalftoneBrush`）。
   远看是"黄底带印刷颗粒"，近看才是点；**不要网点就把这一个键换成 `PopYellowBrush`**。
4. **硬黑框 + 直角**：卡片、按钮、输入框、下拉一律 2px 纯黑描边，圆角全 0。
5. **文字黑**，白字只出现在深色块上（黑/红/蓝底）。
6. **语义色保留高饱和**（红 `#E4002B` / 绿 `#00A651` / 橙 `#FF8A00` / 蓝 `#0057FF`），
   并一律配 2px 黑框——它们也是"色块"，不是小灰标签。
7. **主按钮每屏只用一次**（拍一张 / 运行 / 识别并新增）；危险动作（批准执行、
   删除上下文）红底白字。

### 模块怎么"稍微丰富"

- 页面标题：黄点方块 `PageTitleMark` + 24px 粗黑标题
- 面板型卡片（设备列表/预览/指标/审计/自检/答复）：`CardHeaderBar` 白底 + 1px 黑底线
- 内容型卡片（参数/说明/设置小节）：`SectionTitleRow` = 黄点小块 + 粗标题
- 选中行：黄网点底 + 左侧 3px 黑条；悬停：淡黄（`HoverBrush`）

### 卡片硬投影：试过，不做

给卡片加 `DropShadowEffect`（0.5~10px 无模糊偏移）想要"贴纸影子"，
实测在 2px 黑框旁边读不出影子，只是把右下边框加粗、显得不齐，已移除。
要恢复：在 Tokens 定义 `PopShadow`，再给 `CardBorderStyle` 加 `Effect` setter。

### 调色卡（主色可换）

顶栏「调色」→ 弹出 8 格色卡，点一下整站换主色，选完立即生效并记住。

| 环节 | 落点 |
|---|---|
| 主色槽位（5 个键） | `AccentBrush` / `AccentHoverBrush` / `AccentDeepBrush` / `AccentSoftBrush` / `AccentHalftoneBrush`，外加 `TextOnAccentBrush`（主色上的文字色，按亮度自动黑/白） |
| 换色实现 | `Services/ThemeService.cs`：把上面几个键整体替换进 `Application.Resources`，`DynamicResource` 引用方自动刷新 |
| 记住 | 统一的 JSON 设置存储，键 `appearance`（`%LocalAppData%\CameraControl\appearance.json`） |
| 界面 | `MainWindow.xaml` 顶栏 ToggleButton + Popup；色卡是 `ViewModels/AppearanceViewModel.cs` 的 `Swatches` |
| 加新主色 | 在 `ThemeService.Presets` 里加一行 `new("pop-xxx", "名字", Color.FromRgb(...))`，色卡自动多一格 |

**硬约束：样式里引用主色必须用 `{DynamicResource Accent*}`。**
`StaticResource` 会在加载时把某一个刷子实例焊死在样式里，之后换色完全不生效，
而且界面不会报任何错——冒烟测试里的「调色卡换主色」就是拦这个的。

大部分是**隐式样式**（Button/TextBox/ComboBox/CheckBox/RadioButton/ListBoxItem/

### 两个坑（都已踩过，写下来防复发）

1. **模板里的 `StaticResource` 看不到 `App.xaml` 的内联资源。**
   `ControlTemplate` 只往它所属字典的 `MergedDictionaries` 里找。
   所以转换器单独放在 `Converters.xaml`，`Controls.xaml` 自己合并它。
2. **自定义 ComboBox 模板不会替你做 `DisplayMemberPath`。**
   系统默认模板会把选中项折算成显示文字，自己写的模板只拿到对象 → 收起状态显示类名
   （`CameraControl.Presentation.ViewModels.CameraRowViewModel`）。
   现在由 `Services/DisplayMemberConverter` 在模板里补上，用 `DisplayMemberPath` 的组合框
   自动正确。

## 四、人工确认弹窗（P4 的关键解锁）

这是"AI 能操作物理设备"的前置条件。

```
⚠ AI 请求执行一个需要人工确认的操作
┌──────────────────────────────────────┐
│ 操作      机器人运动                   │
│ 能力 id   robot.moveTo                │
│ 风险等级  Physical（会驱动物理设备）    │
│ 发起者    AI（wpf-agent）              │
└──────────────────────────────────────┘
该操作会改变物理设备状态。请确认现场安全后再批准。
                        [拒绝]  [批准执行]
```

**行为约定（有测试锁死）**：

| 场景 | 结果 |
|---|---|
| AI + Physical/Destructive | 弹窗询问；**批准才执行，拒绝绝不执行** |
| AI + Physical，无 UI 宿主（CLI） | **直接拒绝**（失败关闭），不会假装得到确认 |
| 人工点击操作（Human actor） | 视为意图表达，不弹窗 |

关闭窗口、按 ESC、点拒绝 → 一律返回 false。

## 五、架构位置

```
Presentation (WPF)
  ├─ MainWindow / MainViewModel      ← 只做界面粘合，逻辑都在 Application
  ├─ WpfConfirmationGate             ← 实现 Application 的 IConfirmationGate
  └─ FrameToBitmap                   ← FrameImage → BitmapSource（内存，不落盘）
        │
        ▼  唯一入口：ServiceRegistration.Build(options, gate)
Composition → Application → Domain
```

- **Presentation 不被其它层引用**，`Composition` 也不知道界面存在；
  `MainViewModel` 由宿主用 `ActivatorUtilities` 构造。
- 唯一注入点是 `ServiceRegistration.Build(options, confirmationGate)`。
- `app.manifest` 固定 `asInvoker`——**绝不能改成 requireAdministrator**，
  否则摄像头会被 Windows 拒绝（`0x80070005`）。

## 缺陷记录：刷新后弹出多层错误框并闪退（已修）

**现象**：点"刷新"后弹出十几层 `CameraControl` 错误框，随后闪退。

**错误信息**：

```
无法对"CameraRowViewModel"类型的只读属性"KindText"进行 TwoWay 或 OneWayToSource 绑定。
```

**根因**：列表项模板里用多个 `<Run>` 拼接"类型 · id"：

```xml
<Run Text="{Binding KindText}" />   <!-- ✗ -->
<Run Text=" · " />
<Run Text="{Binding Id}" />          <!-- ✗ -->
```

`Run.Text` 的绑定默认模式是 **TwoWay**，而 `KindText`/`Id` 是只读属性 →
每渲染一行就抛一次 `InvalidOperationException`；
`DispatcherUnhandledException` 又为每次异常弹一个框，于是叠了一屏。

> 注意：`TextBlock.Text` 的默认模式是 OneWay，`Run.Text` 却不是——这是 WPF 的经典陷阱。

**修复**（两层）：

1. 改为**单个只读属性 + TextBlock.Text**，从设计上避开 TwoWay 陷阱：

   ```csharp
   public string Subtitle => $"{KindText} · {Id}";
   ```
   ```xml
   <TextBlock Text="{Binding Subtitle, Mode=OneWay}" />
   ```

2. `DispatcherUnhandledException` 改为**只弹一次**，其余仅写日志（含内部异常与堆栈），
   避免任何异常都能造成"弹窗风暴"。

**防回归**：新增 `XamlBindingGuardTests`，静态扫描 `src/**/*.xaml`，
发现 `<Run Text="{Binding ...}" />` 直接失败，并在失败信息里说明原因。

**附带发现（非代码缺陷）**：从 Visual Studio 以**管理员身份**启动时，
自检会报 `process.elevation` 失败——Windows 拒绝高完整性进程访问摄像头（`0x80070005`）。
必须**以普通用户身份**启动（直接双击 exe）。

## 缺陷记录 2：每次关闭程序都报 InvalidOperationException（已修）

**现象**：关闭窗口时抛出

```
System.InvalidOperationException
  Message='CameraControl.Application.Capture.CameraSessionRegistry' type only
  implements IAsyncDisposable. Use DisposeAsync to dispose the container.
  Source=Microsoft.Extensions.DependencyInjection
  在 CameraControl.Presentation.App.OnExit(...)
```

**根因**：`CameraSessionRegistry` 只实现了 `IAsyncDisposable`。
DI 容器的**同步** `Dispose()` 遇到这种服务会直接抛异常；
而 WPF 的 `OnExit` 只有同步收尾的机会——两者冲突。

**为什么不能简单改成 DisposeAsync().Wait()**：
WinRT 的 `MediaCapture` 收尾需要 STA 线程（创建它的 UI 线程）。
在 UI 线程上同步等待自己的异步续体**必然死锁**。

**修复**：让注册表同时实现两种释放，语义不同：

| 方式 | 行为 | 用在哪 |
|---|---|---|
| `DisposeAsync()` | 逐个 `await` 释放，吞掉单台失败 | 正常运行期、测试 |
| `Dispose()`（同步） | 取出会话，**在当前线程发起** `DisposeAsync`，**不等待**完成，异常经 `ContinueWith` 观察掉 | 应用退出 |

同时 `App.OnExit` 整体加了 try/catch + 日志——**退出路径的释放一律不得再抛**，
否则只会变成"关不掉"或关停崩溃弹窗。

**防回归**：`CameraSessionRegistryDisposeTests`，其中一条直接复现线上场景：

```csharp
services.AddSingleton<ICameraSessionRegistry>(...);
using ServiceProvider provider = services.BuildServiceProvider();
_ = provider.GetRequiredService<ICameraSessionRegistry>();
provider.Dispose();   // 这一步原先就会抛
```

**实测**：`dotnet CameraControl.dll --smoke-test` 退出码 0、stderr 为空、无该异常。
