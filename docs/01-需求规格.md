## 1. 目的与范围

### 1.1 目的
定义 v2.0 的功能与非功能需求，作为设计、开发、测试与验收的基线。

### 1.2 系统边界

本系统为**单机部署的机器视觉工位控制软件**，运行于 Windows 工控机，负责：

- 多台工业相机 / UVC 摄像头的接入、参数配置与图像采集
- 光源控制
- 二维标定（九点 / 手眼）与坐标系换算
- 机器人位姿读取与运动协同
- 与上位系统（PLC / MES / 其它软件）的 TCP 通讯
- 触发规则的编排与执行
- 记录、追溯与审计
- **AI 编排（CUA）**：配置大模型 API 后，由 AI 通过命令总线操控本软件

**不在范围内**：图像算法检测（缺陷识别等）、多机位中央调度、云端管理平台。

### 1.3 术语

| 术语 | 含义 |
|---|---|
| 相机会话（Session） | 一台相机的一次打开→取流→关闭生命周期 |
| 帧（Frame） | 一次采集得到的图像及其元数据 |
| 能力（Capability） | 一个可被调用、有 schema、有风险等级的原子命令 |
| 命令总线（CommandBus） | 人（UI）与 AI 共用的唯一执行入口 |
| 风险等级 | ReadOnly / Reversible / Physical / Destructive |
| 确认门（Confirmation Gate） | 高风险命令执行前要求人工确认的闸门 |
| 端口（Port） | 领域层定义、基础设施层实现的接口 |

## 3. 功能需求

> 每条含**验收准则（AC）**，作为测试用例来源。编号 `FR-x.y`。

### FR-1 设备接入与发现

| 编号 | 需求 | 验收准则 |
|---|---|---|
| FR-1.1 | 支持通过厂商 SDK 枚举工业相机（海康 MVS：GigE / USB3 Vision / GenTL） | 枚举结果含厂商、型号、序列号、接口类型、IP/MAC；枚举不打开设备 |
| FR-1.2 | 支持枚举本机 UVC 摄像头（含笔记本内置） | 能识别并标记红外（IR）摄像头；IR 设备不可取流 |
| FR-1.3 | 支持局域网被动发现（ARP + 厂商 OUI） | 默认零网络报文；结果为「仅检测」，不可连接 |
| FR-1.4 | 支持 ONVIF 主动发现（可关闭） | 默认关闭；仅发送标准 WS-Discovery Probe；不认证、不取流 |
| FR-1.5 | 设备台账可持久化 | 重启后设备清单、别名、参数选择全部恢复 |
| FR-1.6 | 支持设备热插拔检测 | 拔插后 3 秒内清单状态更新，不崩溃 |
| FR-1.7 | 设备身份稳定 | 同一物理设备重复扫描不产生重复条目；改名后仍识别为同一设备 |

### FR-2 相机会话与采集

| 编号 | 需求 | 验收准则 |
|---|---|---|
| FR-2.1 | 支持单帧采集 | 调用返回一帧图像；超时可配置；失败有明确错误码 |
| FR-2.2 | 支持连续采集与停止 | 帧率可观测；停止后无残留帧引用 |
| FR-2.3 | 支持软触发采集 | 触发一次出一帧 |
| FR-2.4 | 支持像素格式转换 | Mono8 / RGB8 / BGR8 / BGRA8 / Bayer 均可显示 |
| FR-2.5 | 相机参数可读写 | 曝光、增益、触发模式等；参数页动态生成 |
| FR-2.6 | 采集失败可重试 | 指定重试次数与退避策略；每次失败留痕 |
| FR-2.7 | 会话隔离 | 单台相机异常不影响其它相机会话 |

### FR-3 多相机同步采集（D5）

> **业务场景**：当前是单相机 + 单机械臂。未来目标是**单机械臂 + 多相机同时对准同一作业区域**，
> 从不同角度**同步拍照**，做多视角融合 / 3D 定位，解决精细或大尺寸工件的遮挡问题。
>
> **重要定性**：这不是"多路连续视频流"，也不是"多台相机轮流拍"，而是
> **事件触发的同步单帧采集**：机械臂到位 → 多台相机同步曝光各拍一帧 → 返回多帧 + 统一时间戳 → 融合。
>
> **P0 只实现单相机**，但**契约必须按 N 台设计**，未来加相机不改调用方。

| 编号 | 需求 | 验收准则 |
|---|---|---|
| FR-3.1 | 采集接口必须是**组**语义 | 调用方拿到的永远是 `CaptureGroupResult`（含帧列表），单相机时列表长度为 1；**加相机不改调用方代码** |
| FR-3.2 | 组结果必须携带**组级统一时间戳** | `CaptureGroupResult` 含 `TimestampUtc` + `TimestampQuality`（硬件打标/软件近似） |
| FR-3.3 | 组结果必须报告**实测偏斜（Skew）** | 每帧携带相对组时间戳的偏移；融合层可据此判断是否可用 |
| FR-3.4 | 触发方式必须抽象为参数 | `TriggerSpec { Kind: Software / Hardware, HardwareSourceId }`；调用方只换参数 |
| FR-3.5 | **P0 只实现 `Software` 分支** | 软件触发可用；`Hardware` 分支返回 `NOT_IMPLEMENTED` 但契约已就位 |
| FR-3.6 | **P2 实现 `Hardware` 分支** | 支持外部硬触发源（PLC / 光源控制器）；多相机同步曝光 |
| FR-3.7 | 同步采集要有"武装/解除"生命周期 | `Arm(TriggerSpec)` → 等待事件 → 帧组 → `Disarm()`；硬触发时相机需提前进入等待态 |
| FR-3.8 | 预览会话仲裁 | 同一时刻仅一台相机进入 UI 预览；切换时先释放上一路 |
| FR-3.9 | 相机级配置模板 | 可对同型号相机批量套用参数（多相机时的关键效率点） |
| FR-3.10 | 资源保护 | 超出会话上限时**拒绝并给出原因**，不静默降级 |
| FR-3.11 | 故障隔离 | 单台相机采集失败不应让整组静默返回"部分成功"；必须显式标记缺失相机 |

### FR-3a 多视角融合（未来，本期不实现但需预留数据形态）

| 编号 | 需求 | 验收准则 |
|---|---|---|
| FR-3a.1 | 组结果需含每台相机的**标定/位姿关联** | 帧携带 `CameraId`，可关联到该相机的外参 |
| FR-3a.2 | 组结果可序列化为融合算法输入 | 导出结构稳定、带 schema 版本 |
| FR-3a.3 | 预留 `IPointCloudFusion` 端口 | P0 只定义接口，不实现 |

### FR-3b 采集就绪判定（振动衰减门）—— **关键工艺要求**

> **不许"发完停止指令立即拍"**。机械臂停止后仍有残余微振，会直接污染高精度融合。
> 触发条件必须是：**振动衰减到阈值以下并持续稳定一段时间**。

| 编号 | 需求 | 验收准则 |
|---|---|---|
| FR-3b.1 | 采集前必须有**就绪门（Readiness Gate）** | 采集流程为：`就绪 → 武装 → 触发 → 取组`，门未通过不得触发 |
| FR-3b.2 | 就绪判据必须包含**振幅阈值 + 持续时长** | `ReadinessCriteria { MaxAmplitude, StableDuration, Timeout }`；两者同时满足才算就绪 |
| FR-3b.3 | 支持多种就绪判据来源，可插拔 | `RobotReported` / **`VisionBased`** / `ExternalSensor` |
| FR-3b.4 | **优先实现视觉判据** | 用相机自身做振动传感器：连拍短序列，测帧间位移，位移持续低于阈值即就绪（无需额外硬件） |
| FR-3b.5 | 就绪判定结果必须回报 | 返回实测振幅、等待时长、判据来源，便于调参与追溯 |
| FR-3b.6 | 超时处理明确 | 超过 `Timeout` 仍未就绪 → 返回 `NOT_SETTLED`，**不得降级为"拍一张试试"** |
| FR-3b.7 | 机器人"到位"只是**粗判据** | 可用来提前开始探测以省节拍，但**不能**代替振动判据 |

### FR-3c 运动冻结采集（P2 后期，节拍不足时启用）

> 硬触发同步只解决"多视角之间同一时刻"，**不解决单视角内的运动模糊**。
> 若臂仍在动就曝光，必须同时具备**四件套**，缺一不可。

| 编号 | 需求 | 验收准则 |
|---|---|---|
| FR-3c.1 | 位置触发 | 由编码器 / PLC 到位脉冲触发，**不是软件定时** |
| FR-3c.2 | 频闪光源 | 常亮光下极短曝光会欠曝，**频闪是刚需**；频闪与曝光同一脉冲对齐 |
| FR-3c.3 | 短曝光 | 曝光时间可设至几十~几百 µs |
| FR-3c.4 | 多相机同一脉冲 | 所有相机挂在**同一**触发脉冲上，不允许各相机独立触发 |
| FR-3c.5 | 曝光/频闪预算校验 | `曝光 ≤ 频闪时长 + 余量`；不满足则拒绝配置并说明原因 |
| FR-3c.6 | 运动模糊预算校验 | 按 `模糊(px) = 速度 × 曝光 ÷ 像素尺寸` 估算；超阈值则拒绝或告警 |
| FR-3c.7 | 采集模式参数化 | `CaptureMode { StaticSettled, MotionFrozen }`；P0/P2 初期只用 `StaticSettled` |
| FR-3c.8 | 阶段可回退 | 若动态抓拍精度不达标，可切回静止采集，不改调用方代码 |

## 4. 非功能需求

| 编号 | 类别 | 要求 | 验收方式 |
|---|---|---|---|
| NFR-1 | **可测试性** | Domain/Application 层单元测试覆盖率 ≥70%；核心用例可在无 UI、无硬件下用假实现跑通 | `dotnet test` + 覆盖率报告 |
| NFR-2 | **可观测性** | 结构化日志（Serilog）；关键路径耗时埋点；全量操作审计 | 日志字段齐全、可查询 |
| NFR-3 | **安全性** | 物理动作默认需确认；软限位；速率限制；急停；AI 权限可收紧 | 安全用例集通过 |
| NFR-4 | **隐私** | UVC/内置摄像头画面**只进内存**；任何落盘必须过策略闸门；AI 同样受限 | 磁盘文件数=0 断言（已有先例） |
| NFR-5 | **性能** | 预览 ≥30 fps（1080p）；命令响应 <100 ms（不含硬件动作） | 性能基准测试 |
| NFR-6 | **可靠性** | 断线重连；设备热插拔；**禁止空 catch**；UI 线程无阻塞调用 | 静态检查 + 故障注入 |
| NFR-7 | **可部署性** | 单机离线；**普通用户权限运行**（管理员权限会导致摄像头不可用）；明确 x64 | 在目标机验证 |
| NFR-8 | **可维护性** | 依赖方向由项目引用强制；新代码**零警告**；统一 `.editorconfig` | CI 门禁 |
| NFR-9 | **兼容性** | 海康 MVS SDK、YMConnect 私有库薄包装，升级不影响上层 | 适配器层隔离验证 |
| NFR-10 | **可扩展性** | 新增相机厂商/机器人品牌 = 新增适配器，不改 Application | 代码评审 |
| NFR-11 | **同步精度** | 硬件触发模式：多相机帧间偏斜 **≤ 1 ms**（目标 ≤ 100 µs）；软件触发模式：记录实测偏斜，不承诺上限 | 双相机对拍秒表/闪烁 LED 实测 |
| NFR-12 | **时间戳可信度** | 结果必须区分 `HardwareStamped` / `SoftwareApprox`，融合层不可把软件时间戳当硬同步用 | 类型层面禁止混用 |
| NFR-13 | **静止判定精度** | 视觉就绪门可分辨的位移量级应优于融合精度要求（建议 ≤ 0.1 px 或 ≤ 0.02 mm） | 人为施加微振的复现测试 |
| NFR-14 | **运动模糊预算** | `MotionFrozen` 模式下模糊量可估算并可配置阈值；超阈值必须拒绝或告警 | 公式校验 + 实拍验证 |

## 5. 安全需求（专项）

### 5.1 风险分级

| 等级 | 定义 | 例子 | AI 可直接执行 |
|---|---|---|---|
| ReadOnly | 不影响状态 | 读参数、查设备、读位姿 | ✅ |
| Reversible | 可轻易撤销 | 改曝光、改亮度、切坐标系 | ✅（留痕） |
| **Physical** | **引起物理运动** | 机器人运动、设当前位姿 | ❌ 需确认 |
| Destructive | 不可逆/丢数据 | 删设备、清空标定、改 IP | ❌ 需确认 + 二次校验 |

### 5.2 强制设施

- **确认门**：Physical/Destructive 命令在无人工确认时返回 `ConfirmationRequired`
- **软限位**：应用层校验机器人目标在工作空间内，**不信任 AI**
- **速率限制**：单位时间内物理命令数上限
- **急停**：可中断执行中的命令链
- **审计**：每次命令记录 actor（Human/Ai）、命令、参数、结果、耗时
- **AI 授权模式**：默认「需确认」；可在设置中临时提权，且自动过期
