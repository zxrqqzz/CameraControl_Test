### 关键测试用例（锁死契约）

| 用例 | 意义 |
|---|---|
| 单相机返回 1 帧、`SoftwareApprox`、`Skew=0` | P0 组语义正确，未来加相机不改调用方 |
| 多相机组时间戳取最早帧、`Skew` = 最大时间差 | 融合对齐基准正确 |
| 缺相机必须出现在 `missingCameras` | 禁止静默部分成功 |
| 相机未打开 → `CAMERA_NOT_OPEN` | 明确错误码 |
| 就绪门未过 → `NOT_SETTLED` 且**不触发采集** | 振动门是真的闸门，不是摆设 |
| 硬件触发 → `TRIGGER_MODE_NOT_IMPLEMENTED` | 契约就位、实现待 P2 |
| `MotionFrozen` → `TRIGGER_MODE_NOT_IMPLEMENTED` | 同上 |
| **AI 调 `robot.moveTo` → `CONFIRMATION_REQUIRED` 且处理器未执行** | CUA 安全模型核心 |
| 被拒绝的命令也写审计 | 安全事件可追溯 |
| 曝光/模糊预算 6 组边界 | P2 动态抓拍的质量闸门先定死 |
| 位移测量：整数 ±0.1px、亚像素 ±0.2px、纯色图判不可信 | "相机当振动传感器"的数学内核可信 |

## 三、怎么跑

### 编译 + 测试
```powershell
cd D:\Xjk\C#\Test\CameraControl
dotnet build CameraControl.slnx
dotnet test  CameraControl.slnx
```

### 离线连拍分析（需要真相机）

```powershell
cd tools\CameraControl.Tools.BurstAnalyzer
dotnet run -- --help
```

**baseline（测噪声底）** —— 机械臂完全静止 ≥5 秒后：
```powershell
dotnet run -- --mode baseline --frames 60 --out D:\temp\baseline.json
```

**settling（测衰减）** —— 开始采集的瞬间扰动机器人：
```powershell
dotnet run -- --mode settling --frames 80 --interval-ms 30 --out D:\temp\settling.json
```

> 没给 `--fusion-accuracy-mm` 时结论为 `Undetermined`，只出数据；
> 将来定了精度目标再补 `--fusion-accuracy-mm 0.1 --scale-mm-per-px 0.005` 就能出 `Viable/NotViable`。

**默认不落盘**：图像只在内存参与计算，只写报告 JSON。

## 五、已知取舍（需要知道的设计决定）

| 取舍 | 原因 |
|---|---|
| P0 就绪门是 `FixedDelayGate` | 不假装做了振动判定；真判定需先用 BurstAnalyzer 验证可行性 |
| `CaptureSingleAsync` 每次重启取流 | 海康会话未做常驻流；对 BurstAnalyzer 的帧率有影响，报告里如实给出实测间隔 |
| 审计日志先落 JSONL 文件 | 简单可靠、崩溃不损坏；量大后再换 SQLite |
| 未接 Serilog | P0 用审计日志兜住可观测性，UI 层再补结构化日志 |
| 旧单工程已从工作区删除 | 备份在 `master` 分支；业务逻辑按 P1/P2/P5 逐步迁移，不在 P0 一次性搬 |
