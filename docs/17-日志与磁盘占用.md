# 17 · 日志与磁盘占用

> 背景：2026-11-13 发现"引入主题样式后仓库从约 400 MB 涨到 850 MB，VS 编译崩了 3 次"。
> 排查结论：**不是主题 XAML 的锅**（`Themes/` 共 0.1 MB），是日志无上限 + 构建产物残留。
> 本文记录根因与已落地的加固，避免复发。

---

## 一、当时的数字

| 项目 | 体积 | 说明 |
|---|---|---|
| `data\logs\app-20261113.log` | **447.8 MB** | 单日单个文件，就是它把仓库撑了一倍 |
| 过期 TFM 构建产物（`net10.0-windows`） | **106.8 MB** | 目标框架改过一次，旧目录没被清掉，同一份 DLL 存了两份 |
| 根目录 `CameraControl\`（旧单工程残留） | 0.3 MB | 只剩 obj，没有源码 |
| bin/obj（正常构建产物） | ≈ 290 MB | 大头：`Microsoft.Windows.SDK.NET.dll` 23.7 MB × 5 份、OpenCvSharp 原生 65 MB + 27 MB |
| 源码（不含 bin/obj/data） | ≈ 6.7 MB | 其中主题字典 0.1 MB |

---

## 二、根因

### 1. 日志没有体积上限

`ConfigureSerilog` 原来只按天滚动（`RollingInterval.Day`，保留 14 天），**没有单文件上限**。
一天写多少就是多少。

### 2. 一次模板错误在布局循环里重复抛出

开发调样式期间，`Themes/Controls.xaml` 里的转换器引用一度找不到
（`StaticResource DisplayMember` 未合并），WPF 在**每次布局/测量**都会重新抛
`XamlParseException`，而 `DispatcherUnhandledException` 每次都写一条**带完整堆栈**
（约 7 KB）的错误日志。几分钟内累计六万余条 → 447.8 MB。

> 这类异常的特点是：**界面还在"半死"状态继续跑**，异常被一层层吞掉重试，
> 所以不会立刻崩，只会安静地把磁盘写满。

### 3. 旧目标框架的输出没人清

`Directory.Build.props` 把 TFM 从 `net10.0-windows` 提到
`net10.0-windows10.0.19041.0` 之后，旧目录留在 `bin/` 里不会自动删除。

## 三、已落地的加固

### 1. 日志硬上限（`Composition/ServiceRegistration.cs`）

```csharp
.WriteTo.File(
    "app-.log",
    rollingInterval: RollingInterval.Day,
    retainedFileCountLimit: 10,
    fileSizeLimitBytes: 10 * 1024 * 1024,   // 单文件 10 MB
    rollOnFileSizeLimit: true,              // 超了滚动成 app-yyyyMMdd_001.log
    shared: false);
```

日志目录**最大占用约 100 MB**（10 个 × 10 MB），不会再出现单文件 448 MB。

### 2. 未处理异常按签名节流（`App.xaml.cs`）

- 判重键：`异常类型 | 消息 | 堆栈首行`
- 60 秒窗口内同一签名只完整记一次；之后只计数，每累计 100 次补一条
  「同类异常已重复 N 次」
- 判重表超过 200 条会清空一次，防止异常种类太多把内存吃掉

### 3. WPF 绑定告警去重（`Diagnostics/WpfBindingTraceListener.cs`）

绑定错误会按数据项/按布局轮次重复触发。现在：

- 同一条文本只记一次，重复的直接丢弃
- 最多跟踪 200 条不同问题，超了只提示一次「后续不同条不再写入日志」

### 4. 构建产物清理脚本（`scripts/clean-build.ps1`）

```powershell
# Windows PowerShell（本机没有 pwsh 时用这个）
powershell -NoProfile -ExecutionPolicy Bypass -File scripts\clean-build.ps1 -All

# 三档：
#   （无参数）  只清 bin/obj
#   -StaleTfm  只清"过期目标框架"目录（默认 net10.0-windows）
#   -All       两者都清
```

> 脚本带 UTF-8 BOM 保存：Windows PowerShell 5.1 会按 ANSI 解析无 BOM 的 .ps1，
> 中文注释会被截断成语法错误。以后改这个脚本也用带 BOM 的 UTF-8。

实测：全量清理回收 289.7 MB，仓库回到 6.7 MB；重新构建后约 293 MB（正常产物）。

## 四、日常怎么维护

| 场景 | 做法 |
|---|---|
| 感觉磁盘又变大了 | 先看 `data\logs` 单文件大小；超 10 MB 说明上限没生效，查 Serilog 配置 |
| 要腾空间 | 跑 `scripts\clean-build.ps1`（bin/obj 随时可丢，重建即可） |
| VS 变慢 / 卡顿 | 把 `data\`、`bin\`、`obj\` 从 VS 的"文件索引/搜索"里排除；`artifacts\` 也可删 |
| 看日志 | `data\logs\app-yyyyMMdd*.log`（UTF-8，含结构化字段） |
| 交付前 | 跑一次清理脚本 + `dotnet build`，确认干净构建能过 |

## 五、判据（防回归）

- 冒烟测试 15/15 通过（含三个窗口的 XAML 解析、调色卡换主色）
- 单次启动写入日志的量级：**几百字节**（正常）；若某次启动后日志暴涨，
  说明又有异常在循环里被反复抛出，看 `[ERR] 未处理的异常` 的签名即可定位
