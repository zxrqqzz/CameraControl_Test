## 3. 领域核心类型（同步采集）

> 这些类型是**契约的地基**，先定死，P0 单相机也要按它返回。

```csharp
public readonly record struct CameraId(string Value);

public enum TriggerSourceKind { Software, Hardware }

/// 触发方式抽象：调用方只换参数，不换代码
public sealed record TriggerSpec(
    TriggerSourceKind Kind,
    string? HardwareSourceId = null,   // P2：PLC / 光源控制器通道
    int SoftwareDelayUs = 0);

/// 时间戳可信度：类型级区分，防止软同步被当硬同步用
public enum TimestampQuality { HardwareStamped, SoftwareApprox }

public sealed record Frame(
    string FrameId,
    CameraId CameraId,
    DateTimeOffset TimestampUtc,
    TimeSpan OffsetFromGroup,       // 相对组时间戳的偏移
    int Width,
    int Height,
    string PixelFormat);

/// 采集结果：永远是"组"，单相机时 Frames.Count == 1
public sealed record CaptureGroupResult(
    string GroupId,
    DateTimeOffset TimestampUtc,          // 组级统一时间戳（融合对齐基准）
    TimestampQuality TimestampQuality,
    TimeSpan Skew,                        // 实测帧间最大偏斜
    IReadOnlyList<Frame> Frames,
    IReadOnlyList<CameraId> MissingCameras);   // 禁止静默部分成功

public sealed record CaptureGroupRequest(
    IReadOnlyList<CameraId> CameraIds,
    TriggerSpec Trigger,
    TimeSpan Timeout,
    bool ArmFirst = false);

// ── 采集模式（工艺阶段）──────────────────────
public enum CaptureMode
{
    /// P0 ~ P2 初期：机械臂静止 + 振动衰减到阈值以下再拍
    StaticSettled,
    /// P2 后期（节拍不足时）：运动中同步冻结
    MotionFrozen
}

// ── 就绪判定（不许"发完停止指令立即拍"）─────
public sealed record ReadinessCriteria(
    double MaxAmplitude,            // 振幅阈值（px 或 mm）
    TimeSpan StableDuration,        // 需持续稳定的时长
    TimeSpan Timeout,
    ReadinessSource PreferredSource);

public enum ReadinessSource
{
    RobotReported,                  // 机器人报告到位（仅粗判据，不能单独使用）
    VisionBased,                    // 用相机自身做振动传感器（推荐）
    ExternalSensor                  // 外部加速度计/振动传感器
}

public sealed record ReadinessResult(
    bool Ready,
    double MeasuredAmplitude,
    TimeSpan Waited,
    ReadinessSource Source);

// ── 曝光/频闪预算（MotionFrozen 必备）───────
public sealed record ExposureProfile(
    int ExposureUs,                 // 曝光时间
    int StrobeDurationUs,           // 频闪时长
    int StrobeLeadUs = 0);          // 频闪提前量（对齐延迟）

// ── 相机安装形态 ────────────────────────────
public enum CameraMountKind
{
    EyeInHand,                      // 装在机械臂上（当前）
    EyeToHand                       // 固定在工作区（未来）
}
```

> `CaptureGroupRequest` 需追加：`CaptureMode Mode`、`ReadinessCriteria? Readiness`、`ExposureProfile? Exposure`。
> 这些字段 P0 就要存在（可为默认值），否则 P2 会改调用方签名。

**关键**：`Frames` 是列表而不是单帧。P0 只有 1 台相机时 `Frames.Count == 1`；
未来加相机，**调用方一行代码都不用改**。

## 4. 端口（Domain/Ports）

```csharp
// ── 相机 ────────────────────────────────────
public interface ICameraProvider
{
    Task<IReadOnlyList<CameraDescriptor>> DiscoverAsync(CancellationToken ct);
    Task<ICameraSession> OpenAsync(CameraId id, CameraOpenOptions options, CancellationToken ct);
}

public interface ICameraSession : IAsyncDisposable
{
    CameraId Id { get; }
    CameraDescriptor Descriptor { get; }
    bool IsOpen { get; }

    Task SetParameterAsync(string name, string value, CancellationToken ct);
    Task<string?> GetParameterAsync(string name, CancellationToken ct);

    /// 武装：进入等待触发状态（软触发置触发模式；硬触发置等待态）
    Task ArmAsync(TriggerSpec trigger, CancellationToken ct);
    Task DisarmAsync(CancellationToken ct);

    /// 单帧（无武装的即取即用，用于预览/调试）
    Task<Frame> CaptureSingleAsync(CaptureOptions options, CancellationToken ct);
}

// ── 触发源 ──────────────────────────────────
public interface ITriggerSource
{
    TriggerSourceKind Kind { get; }
    /// P0：软件触发（对已武装的相机会话下发 TriggerSoftware）
    /// P2：硬件触发（等待 PLC 信号，不主动下发）
    Task FireAsync(CancellationToken ct);
}

// ── 就绪门（振动衰减判定）───────────────────
public interface IReadinessGate
{
    Task<ReadinessResult> WaitAsync(ReadinessCriteria criteria, CancellationToken ct);
}

// ── 频闪控制（MotionFrozen 必备）────────────
public interface IStrobeController
{
    /// 与相机曝光同一脉冲触发的频闪
    Task FireAsync(string channelId, int durationUs, int leadUs, CancellationToken ct);
}

// ── 曝光/运动模糊预算校验 ───────────────────
public interface IExposureBudgetValidator
{
    /// 校验：曝光 ≤ 频闪时长 + 余量；模糊量 ≤ 阈值
    BudgetCheck Validate(ExposureProfile profile, double velocityMmPerSec, double pixelSizeMm);
}

// ── 机器人（高风险）─────────────────────────
public interface IRobotClient
{
    Task<RobotPose> GetPoseAsync(CancellationToken ct);
    Task<bool> IsInSoftLimitAsync(RobotPose target, CancellationToken ct);
    Task MoveAsync(RobotPose target, MotionOptions options, CancellationToken ct);
    Task StopAsync(CancellationToken ct);
}

// ── 隐私 ────────────────────────────────────
public interface IImagePersistencePolicy
{
    bool IsAllowed(CameraDescriptor camera, ImagePurpose purpose);
}

// ── 存储 ────────────────────────────────────
public interface ISettingsStore { T Load<T>(string key) where T : new(); void Save<T>(string key, T value); }
```

## 5. 同步采集编排（Application 层）

```
CaptureGroupService.CaptureAsync(request)
   │
   ├─ 0. MotionFrozen 模式：先过 IExposureBudgetValidator
   │     曝光 ≤ 频闪时长 + 余量；模糊量 ≤ 阈值
   │     不通过 → 直接拒绝（BLUR_BUDGET_EXCEEDED），不下发任何动作
   │
   ├─ 1. 解析会话（未打开则报 CAMERA_NOT_OPEN，不自动打开）
   │
   ├─ 2. 【就绪门】StaticSettled 模式：
   │     robot "到位" 只是粗判据，可用来提前开始探测以省节拍
   │     IReadinessGate.WaitAsync(criteria)
   │       → 必须 振幅 < MaxAmplitude 且持续 StableDuration
   │       → 超时 → NOT_SETTLED（绝不降级为"拍一张试试"）
   │         P0 用 FixedDelayGate 占位；P2 用 VisionStabilityGate（相机当振动传感器）
   │
   ├─ 3. ArmFirst ? 并发 ArmAsync(spec) 各会话
   │
   ├─ 4. 解析 ITriggerSource（按 spec.Kind）
   │     ├─ Software  → SoftwareTriggerSource（P0）
   │     └─ Hardware  → HardwareTriggerSource（P2，P0 抛 TRIGGER_MODE_NOT_IMPLEMENTED）
   │     MotionFrozen 时：同一脉冲同时驱动 IStrobeController（频闪与曝光对齐）
   │
   ├─ 5. 并发等待各会话的帧（每会话独立 CancellationToken + 超时）
   │     记录每帧到达时间 → 计算 offset 与 skew
   │
   ├─ 6. 组装 CaptureGroupResult
   │     timestampUtc = min(帧时间) 或 硬触发事件时间
   │     timestampQuality = 硬触发 ? HardwareStamped : SoftwareApprox
   │     missingCameraIds = 超时未到达的相机
   │     robotPoseAtExposure = EyeInHand 时的采集时刻位姿
   │     calibrationVersion = 本次使用的标定版本
   │
   └─ 7. ArmFirst ? 并发 DisarmAsync
```

**P0（单相机）行为**：
- `Frames.Count == 1`
- `TimestampQuality == SoftwareApprox`
- `Skew == TimeSpan.Zero`
- `MissingCameras` 为空（否则视为失败）
- 就绪门为 `FixedDelayGate`（可配置固定延时，诚实占位，不假装是振动判定）

**P2 初期（多相机 + 静止采集）**：
- `TriggerSourceKind.Hardware`，`TimestampQuality == HardwareStamped`
- `Skew` 来自硬件时间戳差值，目标 ≤ 1 ms
- 就绪门换 `VisionStabilityGate`：连拍短序列测帧间位移

**P2 后期（动态抓拍，节拍不足才启用）**：
- `CaptureMode.MotionFrozen` + 四件套：位置触发 + 频闪 + 短曝光 + 同一脉冲
- 先过预算校验，再执行；不达标直接拒绝


**P2（多相机硬触发）行为**：
- `TimestampQuality == HardwareStamped`
- `Skew` 来自硬件时间戳差值
- 任一相机缺失 → `missingCameraIds` 非空，上层决定是否继续融合

## 6. 命令总线与能力

```csharp
public enum RiskLevel { ReadOnly, Reversible, Physical, Destructive }

public sealed record Actor(ActorKind Kind, string? Name, string? SessionId);
public enum ActorKind { Human, Ai }

public interface ICommandBus
{
    Task<CommandResult> ExecuteAsync(ICommand command, Actor actor, CancellationToken ct);
}

public interface ICapabilityCatalog
{
    IReadOnlyList<CapabilityDescriptor> All { get; }
    CapabilityDescriptor? Find(string id);
    string ExportJsonSchema();      // 喂给 LLM
}
```

执行管线：

```
ExecuteAsync
  → 查 Catalog（未知能力 → 拒绝，白名单）
  → 前置条件校验
  → RiskPolicy：是否需要确认
       Physical/Destructive 且 actor=Ai → 触发 ConfirmationGate（界面弹窗）
  → RateLimiter（物理命令限速）
  → Handler
  → AuditLog 落库
  → 结构化 CommandResult
```

## 7. 安全层（不可绕过）

| 组件 | 职责 |
|---|---|
| `RiskPolicy` | 由 `CapabilityDescriptor.Risk` 决定是否需要确认 |
| `ConfirmationGate` | 物理/破坏性命令的人工确认（超时=拒绝） |
| `RateLimiter` | 单位时间物理命令数上限 |
| `SoftLimitGuard` | 机器人目标位姿工作空间校验（**不信任 AI**） |
| `IAuditLog` | 谁/何时/命令/参数/结果/耗时 |
| `IEmergencyStop` | 中断执行中的命令链 |

**失败关闭原则**：能力未声明风险等级 → 默认 `Destructive`。

// 能力（自动收集所有 ICommandHandler）
foreach (var t in typeof(CommandBus).Assembly.GetTypes()
         .Where(t => t.IsClass && !t.IsAbstract
                  && t.GetInterfaces().Any(i => i.IsGenericType
                     && i.GetGenericTypeDefinition() == typeof(ICommandHandler<,>))))
    services.AddTransient(t);

## 11. P0 范围（本次要交付的）

> **P0 目标**：立起骨架 + 打通一条**完整垂直切片**，证明架构成立。
> 不追求功能齐全，追求"**接口形状正确、可测试、可扩展**"。

### 11.1 P0 做什么

| 项 | 交付物 |
|---|---|
| 工程化 | solution 分层、`Directory.Build.props`、中央包管理、`.editorconfig`、`global.json`、CI |
| 横切 | DI、Serilog 结构化日志、审计日志、设置存储（含原子写） |
| 领域 | 同步采集核心类型（`Frame` / `CaptureGroupResult` / `TriggerSpec` / `TimestampQuality` / `CaptureMode` / `ReadinessCriteria` / `ExposureProfile` / `CameraMountKind`）——**即使 P0 用不到也要先定义** |
| 端口 | `ICameraProvider` / `ICameraSession` / `ITriggerSource` / `IReadinessGate` / `IStrobeController` / `IExposureBudgetValidator` / `IImagePersistencePolicy`（后三个 P0 只定义 + 桩实现） |
| 相机 | **一个适配器**（海康，复用已验证代码），单相机 |
| 触发 | `SoftwareTriggerSource`；`HardwareTriggerSource` 返回 `TRIGGER_MODE_NOT_IMPLEMENTED` |
| 就绪门 | `FixedDelayGate`（可配置固定延时，**诚实占位**，不假装是振动判定） |
| 命令 | `ICommandBus` + `ICapabilityCatalog` + 审计 + 风险策略（仅实现 `capture.*` 与 `device.list`） |
| 采集 | `CaptureGroupService`（单相机 → 1 帧，`SoftwareApprox`，先过就绪门） |
| **离线连拍分析** | **`tools/BurstAnalyzer`**：用真实工位数据验证"视觉振动判据"可行性与定参（**不进运行时**，见 11.4） |
| 测试 | Domain + Application 单元测试，覆盖率达标 |
| 运行 | **可无 UI 驱动**（测试或 CLI 即可跑通完整采集流程） |

### 11.2 P0 明确不做

- ❌ 不做 UI 重写（P4）
- ❌ 不做机器人、标定、通讯、触发编排（P5）
- ❌ 不做 AI/LLM 接入（P6）——只留 `ICapabilityCatalog` 与 `IAiAgent` 接口
- ❌ 不做硬触发（P2）
- ❌ 不做视觉振动门 `VisionStabilityGate`（P2）
- ❌ 不做频闪与运动冻结采集（P2 后期）
- ❌ 不做多相机外参标定（P5）
- ❌ 不迁移机器人/标定/通讯（P5，旧代码在 `master` 分支可查）

### 11.4 P0 离线连拍分析工具（`tools/BurstAnalyzer`）

> **定位**：这是**一次性验证 + 定参工具**，不进运行时路径。
> 它回答一个关键问题：**"用相机自身做振动判据，在你们真实工位上到底可行吗？"**
> 如果不可行（噪声底已经超过融合精度要求），P2 就该改方案（换镜头/减振/外部传感器），
> 早发现比 P2 后期返工便宜一个数量级。

**为什么放在 P0**：P0 已经能把相机打开、能连拍、契约已就位——
做这个工具几乎零额外成本，却能提前锁定一个高风险假设。

#### 形态

```
tools/
└─ CameraControl.Tools.BurstAnalyzer/    # 控制台程序
   └─ 复用 Domain/Application 的端口（不引用 Presentation）
```

同时它也是"核心可无 UI 驱动"的**活证明**——如果这个工具写起来别扭，说明分层没做对。

#### 输入参数

| 参数 | 说明 |
|---|---|
| `--camera` | 相机 id |
| `--frames` | 连拍帧数（默认 60） |
| `--interval-ms` | 帧间隔（尽量小，测试相机上限） |
| `--exposure-us` | 曝光时间（固定，避免自动曝光干扰） |
| `--roi` | 分析区域（像素，默认中央 1/4 区域） |
| `--scale-mm-per-px` | 像素当量（可选；给了才能出 mm 结论） |
| `--fusion-accuracy-mm` | **融合精度目标（可选，当前留占位）**。未提供时只输出数据与建议初值，结论为 `Undetermined` |
| `--settle-wait-ms` | 触发移动后等待多久开始连拍（默认 0，即"移动一结束就拍"） |
| `--out` | 报告输出路径 |

#### 算法（P0 用最稳的）

1. 取连拍首帧的 ROI 作模板
2. 后续每帧在搜索窗内做**归一化互相关（NCC）**
3. 峰值处做**抛物线亚像素拟合** → 得到 `dx, dy`
4. 幅值 `A = sqrt(dx² + dy²)`（单位 px，可选换算 mm）

> 不用相位相关（FFT）是为了零依赖、易验证；NCC + 亚像素拟合在平移场景精度足够。

#### 两次测量（关键）

| 测量 | 做法 | 目的 |
|---|---|---|
| **基线噪声底** | 机械臂完全静止 ≥5 s 后连拍 | 得到"设备自身抖动 + 传感器噪声"的下限 |
| **衰减曲线** | 触发一次移动 → 立即连拍 → 记录 A(t) | 得到"多久能稳定" |

**没有基线噪声底，阈值就是拍脑袋定的。** 这是本工具最重要的输出。

#### 报告（JSON）

```jsonc
{
  "camera": "hik:SN001",
  "capture": { "frames": 60, "intervalMs": 33, "exposureUs": 3000, "roi": [600,400,1200,800] },
  "baseline": {
    "noiseFloorPx": 0.08,
    "noiseFloorMm": 0.004,        // 若给了 scale
    "samples": 30
  },
  "settling": {
    "curve": [ { "tMs": 0, "ampPx": 1.42 }, { "tMs": 33, "ampPx": 0.91 } ],
    "reachThresholdMs": 187,
    "plateauPx": 0.09
  },
  "recommended": {
    "maxAmplitudePx": 0.16,       // = noiseFloor × 2（经验初值，未校验）
    "stableDurationMs": 66        // 连续 3 帧低于阈值的时间
  },
  "verdict": "Undetermined",      // Viable | Marginal | NotViable | Undetermined
  "verdictReason": "未提供融合精度目标(--fusion-accuracy-mm)，仅输出数据与经验初值，不做可行性结论",
  "notes": [
    "噪声底 0.08px —— 拿到精度目标后可据此判定是否可行",
    "建议 stableDuration ≥ 66ms 以抵抗单帧抖动"
  ]
}
```

#### 判定规则

| verdict | 条件 | 含义 |
|---|---|---|
| `Viable` | 已给精度目标，且 `noiseFloor`（mm）≤ 目标 ÷ 2 | 视觉判据可用，按 recommended 定参 |
| `Marginal` | 已给精度目标，介于 1/2 ~ 1 倍之间 | 勉强可用，需加大 ROI 或多帧平均 |
| `NotViable` | 已给精度目标，且 > 目标 | **视觉判据不可行**，P2 需换方案（镜头/减振/外部传感器） |
| **`Undetermined`** | **未给精度目标** | **只输出原始数据 + 经验初值，不下结论**（当前默认） |

> **原则**：没有精度目标就不编结论。`recommended.maxAmplitudePx = noiseFloor × 2` 只是
> **经验起点**，报告中必须标注"未校验"，避免以后被误当成已验证阈值使用。

### 11.2a 工艺阶段路线（重要）

| 阶段 | 采集模式 | 就绪门 | 触发 | 说明 |
|---|---|---|---|---|
| **P0** | `StaticSettled` | `FixedDelayGate`（占位） | `Software` | 单相机，先把契约跑通 |
| **P2 初期** | `StaticSettled` | **`VisionStabilityGate`**（相机当振动传感器） | `Hardware` | 多相机同步 + 振动衰减门，验证标定与融合精度 |
| **P2 后期** | `MotionFrozen` | 位置触发（编码器/PLC 到位脉冲） | `Hardware` + 频闪 | 仅在节拍不足时启用；先过曝光/模糊预算校验 |

> 这条路线是用户明确定的：**先静止把精度验证清楚，再上动态抓拍**。
> 若动态抓拍精度不达标，可随时退回 `StaticSettled`，**不改调用方代码**。

## 12. 关键风险与对策

| 风险 | 对策 |
|---|---|
| 契约设计不足，P2 加硬触发要改调用方 | P0 就用 `TriggerSpec` + `CaptureGroupResult`，并用测试锁死形状 |
