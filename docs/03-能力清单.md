# 03 · 能力清单（Capability Catalog）

> 这是 **CUA 的核心资产**，也是"人与 AI 共用命令总线"的契约。
> 每个能力 = 一个原子命令，含 id / 描述 / 参数 schema / 风险等级 / 是否需确认。
>
> 本文件是**设计基线**。实现后应由代码自动导出（`ICapabilityCatalog.ExportJsonSchema()`），
> 保证文档与实现不漂移。

---

## 0. 约定

### 0.1 命名规范

```
<领域>.<对象>.<动作>
```

| 领域 | 含义 |
|---|---|
| `device` | 设备台账（登记/删除/连接） |
| `camera` | 相机会话与参数 |
| `capture` | 图像采集 |
| `light` | 光源 |
| `calibration` | 标定 |
| `robot` | 机器人（**高危**） |
| `comm` | 通讯设备 |
| `trigger` | 触发编排 |
| `system` | 系统/诊断/配置 |
| `cua` | AI 自身控制 |

### 0.2 风险等级与授权

| 风险 | AI 可直接执行 | 说明 |
|---|---|---|
| `ReadOnly` | ✅ | 纯查询 |
| `Reversible` | ✅ | 可撤销的写操作，留痕即可 |
| `Physical` | ❌ | **引起物理运动**，必须人工确认 |
| `Destructive` | ❌ | 不可逆/丢数据，必须确认 + 二次校验 |

### 0.3 统一返回结构

```json
{
  "ok": true,
  "capabilityId": "capture.single",
  "data": { "frameId": "f-000123", "width": 2448, "height": 2048, "deviceId": "hik:SN001" },
  "elapsedMs": 42,
  "warnings": []
}
```

失败时：

```json
{
  "ok": false,
  "capabilityId": "capture.single",
  "error": {
    "code": "CAMERA_NOT_CONNECTED",
    "message": "相机 hik:SN001 未打开",
    "retryable": true,
    "hint": "先调用 camera.open"
  }
}
```

> **错误必须结构化**（code/message/retryable/hint），否则 AI 无法自我纠正。

## 2. 详细定义（示例 3 个）

### 2.1 `capture.group` — 同步分组采集（核心能力）

> **业务语义**：事件触发的同步单帧采集，不是多路视频流。
> 典型流程：机械臂到位 → `capture.group`（trigger=hardware）→ 多相机同步曝光 → 返回帧组 + 统一时间戳 → 融合。
>
> **契约铁律**：调用方永远拿到 `frames` 列表。P0 单相机时长度为 1；未来加相机**不改调用方**。

**触发方式抽象（关键设计）**

| kind | P0 | P2 | 说明 |
|---|---|---|---|
| `software` | ✅ 实现 | 保持 | 软件依次触发；or 补偿延时；如实回报偏斜 |
| `hardware` | ⛔ 返回 `TRIGGER_MODE_NOT_IMPLEMENTED` | ✅ 实现 | 相机进入硬触发等待态，由 PLC/光源控制器同时触发曝光 |

> 这样设计的好处：**AI 和上层代码只改 `trigger.kind`，其余调用不变**。

## 3. 能力清单如何生成与消费

```
① 代码定义
   Application/Capabilities/*.cs
       每个能力一个 class，实现 ICommandHandler + 携带 CapabilityDescriptor
                ↓
② 运行时聚合
   ICapabilityCatalog.All  ← DI 自动收集所有 descriptor
                ↓
③ 导出给 AI
   cua.getCapabilities  → JSON Schema 数组（含 description）
                ↓
④ LLM 决策
   系统提示词 = 能力清单 + 当前状态快照
                ↓
⑤ 执行
   ICommandBus.ExecuteAsync(cmd, Actor(Ai, sessionId))
        → 前置条件校验 → 风险判定 → 确认门 → Handler → 审计
                ↓
⑥ 反馈
   结构化 CommandResult 回到 LLM（成功/错误码/提示）
```

**约束**：
- 能力清单**只能由代码生成**，手写文档仅供评审；CI 校验两者一致
- 任何不在清单里的操作，AI 无法调用（白名单机制）
- 新增能力必须同时声明风险等级，未声明则默认 `Destructive`（失败关闭原则）
