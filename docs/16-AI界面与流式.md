## 二、为什么改成流式

非流式下点击「运行」后，DeepSeek 的思考要几十秒，期间界面没有任何反馈，像卡死。
流式把 `reasoning_content` 与正文逐段吐出，"干等"变成"看着它想"。

实现路径：

```
CuaAgent.RunAsync
  └─ SendAsync
       ├─ provider is IStreamingLlmProvider → ChatStreamAsync(SSE)
       └─ 否则 → ChatAsync（一次性），自动降级
```

- 增量通过 `IProgress<AiProgressEvent>` 上报（`TurnStarted / ReasoningDelta / ContentDelta`）
- 界面：运行中显示**纯文本流**；结束后切换为 **Markdown 渲染**
- 思考面板按轮次分组，每轮再折叠一层

## 三、停止的语义（重要）

当前实现是 **立即中断全部**：取消会一路传到工具执行，
**包括正在跑的相机采集 / 机器人运动**。

风险：硬件可能停在半完成状态（例如轨迹只走了一半）。
如果以后觉得危险，改成"停止后续、等当前工具做完"只需要在总线层拦一下取消令牌，
不用改界面。

## 五、已知限制

1. **没有做流式打字机节流**：每来一个增量就刷新一次 UI。
   超长输出时 `AiLiveAnswer += text` 是字符串拼接（O(n²)），
   极端情况下（几十万字符）会卡；正常对话量级无感。
2. **思考不进上下文**（按选择）：每轮重新生成，省 token。
3. **Markdown 只在结束后渲染**：流式过程中是纯文本，因此会看到 `**` `#` 这类原始符号。

## 六、界面改版：一条对话流（2026-11-13）

页面只剩两块：**out（对话流）** + **in（输入卡）**。

```
┌ out ─────────────────────────────────────────────────┐
│                                      ┌─────────────┐ │  ← 我：右对齐
│  [历史对话从本地上下文读回]           │ 问了什么…     │ │     淡主色 + 2px 黑框
│                                      └─────────────┘ │
│  ▸ 思考过程（2 轮）                                    │  ← 折叠，按轮次再折一层
│  ▸ 执行步骤（2 步）                                    │  ← 折叠 = 工具调用记录
│  相机情况（Markdown 正文）                             │  ← AI：左对齐、无框
│  ┌ 表格 / 代码 / 列表 全部按 Markdown 渲染             │
│  10:26                    本次 3,140 tok ｜ 会话 …     │  ← 点用量弹小框，点任意处关闭
├ in ───────────────────────────────────────────────────┤
│ [ 多行输入框 ]                                         │
│ Enter 发送 · Shift+Enter 换行    deepseek-flash · 强度 High  [发送] │
└───────────────────────────────────────────────────────┘
```

- 消息模型：`ViewModels/ChatMessage.cs`（正文 / 思考各轮 / 执行步骤 / 用量 / 流式状态 / Markdown 文档）
- 历史：`IContextStore.ReadActiveEntries`（新增）→ 启动、换配置、开启新对话时灌入，最近 200 条
- 运行中：该条气泡实时增长（纯文本），结束后换成 Markdown 渲染
- 用量：点气泡右下角那行 → `Popup`（`StaysOpen=False`，点任意处自行关闭），内容 = 本轮明细 + 会话累计 + 当前上下文
- 停止：输入行同一位置的「发送」变成「停止」

### 两个踩过的坑

1. **`TabItem.Foreground` 会继承进页面内容**：选中态把 Foreground 设成主色对比色（黑主色时是白字），
   整页正文变成白底白字。修法：颜色只设到页签标题（`TextElement.Foreground`），不碰 TabItem 自身。
2. **`-p:OutDir="artifacts\\..."` 相对工程目录解析**：调试时一直跑到旧 exe，白白困惑半天。
   目检脚本要用**绝对路径**的 OutDir。

### 补记：用量分层 + 滚轮穿透

- **本轮用量**留在气泡右下角（"本次 3,140 tok"），点开小框看本轮明细 + 当前上下文；
- **会话总消耗**移到 AI 页最底部一行（"本次运行累计 …"），从气泡里剥离，只出现一次；
- Markdown 正文不再自己纵向滚动（高度由内容撑开），横向溢出时用 Shift+滚轮或拖动滑块；
- 滚轮穿透由 `Services/WheelBehavior.cs`（附加属性 `beh:WheelBehavior.PassThrough`）实现：
  普通滚轮转发给外层对话流，Shift+滚轮才横向滚内层。
